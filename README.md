# 本地知识库问答系统
基于RAG检索增强生成技术的私有文档问答助手，支持上传TXT/PDF自动构建知识库，自然语言问答。

## 项目简介
本项目实现了一个轻量级的本地知识库问答Agent，用户上传私有文档后，系统自动完成文本切分、向量化、向量存储，支持通过自然语言查询文档内容，回答基于检索到的原文，有效降低大模型幻觉。

## 技术栈
- 大模型：DeepSeek Chat
- Agent框架：LangChain + LangGraph（create_agent）
- 向量数据库：Chroma
- Embedding模型：bge-small-zh-v1.5（本地部署）
- 前端界面：Gradio
- 文档格式：TXT、PDF

## 核心功能
- 支持TXT/PDF文档上传，自动切分向量化
- 基于Chroma向量数据库的语义相似度检索，精准匹配相关内容
- 基于向量相似度检索，精准匹配相关内容
- Agent自动判断是否检索，支持多轮对话记忆
- 回答基于原文，搭配提示词约束，降低大模型幻觉
- 增量更新知识库，无需重建全库
- Gradio可视化网页界面，开箱即用
- 内置化评测体系，可统计准确率、忠实度、响应延迟

## 项目架构
用户提问 → Agent 判断是否检索 → 向量库相似度检索 → 原文拼入提示词 → 大模型生成回答 → 返回用户

文档上传 → 文本加载 → 语义切分 → 向量化 → 存入 Chroma 向量库

## 异常处理
1.日志级别从高到低依次为DEBUD < INFO < WARNING < ERROR < CRIICAL,级别越高代表事件严重程度越强
- DEBUG：最低级别，记录内部细节，用于事后深度排查问题
- INFO：记录正常操作节点，标记程序正常运行的关键里程碑
- WARNING：记录不符合预期、存在风险、但不影响程序继续运行的事件
- ERROR：记录功能失败、业务流程中断的错误
- CRITICAL：最高级别，记录导致程序整体崩溃的致命错误

2.异常处理的三个原则
- 分层捕获，已知业务错单独提示、未知错全局兜底
- 内外有别，用户看友好提示、日志存完整报错
- 异常必记，不静默吞错，全程可追溯

3.测试问题与修复
空文件上传无友好提示 -> 新增了空内容校验 + 业务异常拦截
大文件被动拦截报错难懂 -> 新增主动大小校验
日志初始化报错 -> 修正setLevel/setFormatter的方法顺序问题

4.可优化方向
- 检索侧加 Rerank、调优切块参数
- 体验侧开流式输出、大文件分批入库
- 功能侧扩展文件格式、增加多会话管理
- 评测侧补充忠实度、召回率评测。
